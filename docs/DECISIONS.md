# DECISIONS.md — القرارات المعمارية

## ADR-001: Shared Schema + RLS لتعدد المستأجرين
- **القرار:** جدول واحد لكل كيان مع `tenant_id` في كل صف. RLS هو طبقة الأمان الحاملة.
- **البديل المرفوض:** Database-per-tenant (تكلفة أعلى، تعقيد تشغيلي).
- **السبب:** العزل على مستوى قاعدة البيانات يمنع تسرب البيانات حتى مع خطأ في كود التطبيق.

## ADR-002: Next.js 14 بدل NestJS منفصل
- **القرار:** Full-stack في مشروع واحد (App Router + Server Actions + API Routes).
- **البديل المرفوض:** Next.js + NestJS منفصل — مضاعفة النشر والصيانة للفريق الحالي.
- **السبب:** سرعة الإطلاق، نشر واحد على Vercel، Server Actions تقلل كود API boilerplate.

## ADR-003: Supabase بدل بناء Backend من الصفر
- **القرار:** PostgreSQL + Auth + Storage + RLS على Supabase.
- **السبب:** RLS أصلي في PostgreSQL، مصادقة بالهاتف جاهزة، تخزين، ونسخ احتياطي تلقائي — بدون إدارة خوادم.

## ADR-004: React 18 + useFormState (لا React 19)
- **القرار:** Next.js 14.2 LTS مع React 18.3، استخدام `useFormState` من `react-dom`.
- **السبب:** الاستقرار. `useActionState` يتطلب React 19 — نرقّي لاحقًا مع Next 15.

## ADR-005: الأسعار بالدينار العراقي كأعداد صحيحة
- **القرار:** `INTEGER` للأسعار (25,000 د.ع) — لا كسور عشرية.
- **السبب:** الدينار العراقي لا يستخدم فلسًا عمليًا. الأعداد الصحيحة تتجنب أخطاء الفاصلة العائمة.

## ADR-006: Soft Delete للمنتجات والطلبات
- **القرار:** `deleted_at TIMESTAMPTZ` بدل DELETE.
- **السبب:** سلامة مراجع order_items التاريخية + استرجاع سهل.

## ADR-007: حماية الملفات السرية
- **القرار:** `service_role` key فقط في متغيرات بيئة الخادم، ولا يُستخدم في العميل أبدًا. بيانات اعتماد التوصيل مشفرة AES-256-GCM.
- **السبب:** مفتاح service_role يتجاوز RLS — تسريبه = اختراق كامل.

## ADR-008: صفحة الهبوط ثابتة (Static)
- **القرار:** `/` صفحة static بدون استدعاءات قاعدة بيانات.
- **السبب:** أسرع تحميل ممكن (First Load 96KB)، تعمل حتى بدون تهيئة Supabase، وتصمد أمام انقطاع قاعدة البيانات.

## ADR-009: تدهور رشيق (Graceful Degradation)
- **القرار:** كل صفحات لوحة التحكم تتحقق من تهيئة Supabase وتعرض رسالة عربية واضحة بدل انهيار.
- **السبب:** أول تجربة للمستخدم بعد النشر يجب أن تكون مفهومة — "قاعدة البيانات غير مُهيأة — طبّق migrations" أفضل من صفحة خطأ 500.
